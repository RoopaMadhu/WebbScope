Import a folder of Xenium runs

Every run in the folder is converted in turn (tissues are found automatically, as in the single-run import), each into its own project, and then all tissues are merged into one project to browse together, grouped by run folder instead of disease subtype. Tissues are named <folder>_T0, <folder>_T1 …; cell types are <folder>_T0: Cluster K (10x clusters are not comparable between runs), and cells start grey. The input is never modified. ← open an existing project · import a single run

Tissue boxes from GeoJSON (optional): the <run>_regions.geojson files an earlier import exported

To separate the tissues on each slide the same way as before. Give the folder that holds the files: the output folder of the earlier batch import (each run's file is in the run's folder there) or the folder they were also saved in. Each run's file is found by its name (<run>_regions.geojson, in the folder or one or two levels down). Its tissue boxes become the run's shapes (a shape that was switched off is loaded switched off), and the detected tissues of that run are switched off (switch one on again in the drawing window). Runs without a file keep their detected tissues. These files only tell the tissues apart; they are not anatomical regions within a tissue.

Writes one <run>_regions.geojson per ticked run into this folder, with the tissue boxes as they are now (including edits to loaded ones), from their outlines alone: no cells or transcripts are read, so it is quick. Available once every ticked run has its tissue boxes, loaded from GeoJSON or built in Review all slides…. Each feature holds the tissue's outline, its name and the slide; a switched-off shape is written too, marked keep: false. Overlapping tissues are not separated: they are written as they are, with a warning.

Optional: Draw… (or click a slide in the review) a rectangle or free-hand shape on a run (as in the single-run import) to split a tissue, join pieces, or cut an area out (untick “use” in the drawing window). You can also rename a detected tissue or switch it off there without drawing anything. Runs without edits keep their automatically detected tissues.

H&E scans (optional): a folder with one .czi or .ome.tif / .ome.tiff per slide

Give a folder holding the H&E scans (and, if you have them, the ImageScope .annotations files; sub-folders up to two levels are searched). Each run is matched to a scan by the numbers in the names (for example …__chip0073__… and Chip-0073_….czi (or .ome.tif)); a run that matches nothing, or several scans equally, is left empty so you can choose. Check the suggestions and change them in the table. Several runs may use one scan. The scans are tiled into _he inside the output folder and shown in the merged project's H&E slide window with a scan selector. They are not aligned to the cells.

Registered H&E images (optional): one .ome.tif / .ome.tiff per tissue, already in the Xenium frame

Shown under or beside the cells (the Images button) in the merged project. Each image goes to the sample whose name is the image's file name (without _warped_he.ome.tif); the merged samples are called <run>_T0, <run>_T1 …, so an index.json that maps image names to those sample ids is usually needed. Images that match nothing are listed in the log. Needs the merge option.

tissue detection settings (same as the single-run page)

Transcript density needs transcripts.parquet of every run (for a .tar.gz or .zip it is extracted first, about 1 GB per run). It is read in a stream, about 0.4 GB and a few seconds per run, and is not imported into the project unless you tick the transcripts option below.
