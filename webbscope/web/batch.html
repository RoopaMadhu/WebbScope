Import a folder of Xenium runs

Every run in the folder is converted in turn (tissues are found automatically, as in the single-run import), each into its own project, and then all tissues are merged into one project to browse together, grouped by run folder instead of disease subtype. Tissues are named <folder>_tissue_N; cell types are <folder>_tissue_N: Cluster K (10x clusters are not comparable between runs), and cells start grey. The input is never modified. ← open an existing project · import a single run

H&E scans (optional): a folder with one .czi or .ome.tif / .ome.tiff per slide

Give a folder holding the H&E scans (and, if you have them, the ImageScope .annotations files; sub-folders up to two levels are searched). Each run is matched to a scan by the numbers in the names (for example …__chip0073__… and Chip-0073_….czi (or .ome.tif)); a run that matches nothing, or several scans equally, is left empty so you can choose. Check the suggestions and change them in the table. Several runs may use one scan. The scans are tiled into _he inside the output folder and shown in the merged project's H&E slide window with a scan selector. They are not aligned to the cells.

Registered H&E images (optional): one .ome.tif / .ome.tiff per tissue, already in the Xenium frame

Shown under or beside the cells (the Images button) in the merged project. Each image goes to the sample whose name is the image's file name (without _warped_he.ome.tif); the merged samples are called <run>_tissue_1, <run>_tissue_2 …, so an index.json that maps image names to those sample ids is usually needed. Images that match nothing are listed in the log. Needs the merge option.
